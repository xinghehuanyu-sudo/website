## Codex 是什么？

一句话概括：**Codex 是 OpenAI 提供的 AI 编程代理。**

它不只是回答代码问题，还可以在获得许可后读取项目文件、修改代码、运行命令、执行测试、分析报错和审查 Git 变更。你可以在 ChatGPT 桌面端、终端 CLI、IDE 扩展或云端使用它。

如果你第一次接触这类工具，可以把 Codex 理解成一位能够实际进入项目工作的结对程序员：你负责给出目标、边界和验收标准，它负责调查、修改和验证，最后仍由你审核结果。

> 本文依据 2026 年 8 月 25 日的 OpenAI 官方文档整理。安装入口、套餐价格和使用限制可能变化，请以文末官方链接和结算页面为准。

## 一、先选择适合自己的使用方式

| 使用方式 | 适合谁 | 特点 |
|---|---|---|
| ChatGPT 桌面端 | 新手、希望图形界面操作的人 | 可选择本地文件夹，适合持续对话和查看修改结果 |
| Codex CLI | 熟悉终端的开发者 | 直接在项目目录工作，编辑、命令和 Git 流程集中在一个终端里 |
| IDE 扩展 | 长时间使用 VS Code 等编辑器的人 | 编写代码时随时提供当前文件和项目上下文 |
| Codex 云端 | 需要长任务、远程执行或 GitHub 协作的人 | 任务可在云端运行，完成后再回来审核结果 |

第一次使用，推荐以下两条路线任选其一：

- **想简单一点：安装 ChatGPT 桌面端，在产品选择器中进入 Codex。**
- **平时习惯终端：安装 Codex CLI，在测试项目里运行一次。**

## 二、安装 ChatGPT 桌面端并使用 Codex

OpenAI 官方桌面应用目前提供 macOS、Windows 和 Linux 版本。

1. 打开 [ChatGPT 官方快速入门](https://learn.chatgpt.com/docs/quickstart)，点击下载入口。
2. 安装并打开 ChatGPT，使用自己的 ChatGPT 账号登录。
3. 在新建任务的产品选择器中选择 **Codex**。
4. 选择一个项目文件夹，确认允许 Codex 访问的范围。
5. 输入任务，例如：

```text
请先阅读这个项目，说明它使用的技术栈、启动命令和主要目录，不要修改文件。
```

了解项目后，再尝试一个小修改：

```text
请给首页标题增加一行副标题。先说明准备修改哪些文件，修改后运行构建检查。
```

> 不要第一次就选择重要项目。先用一个测试目录熟悉文件授权、命令确认、差异查看和撤销流程。

## 三、安装 Codex CLI

### macOS / Linux：官方安装脚本

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
codex --version
```

同一条安装命令也可以用于更新 Codex。

### 使用 npm 安装

如果电脑已经安装 Node.js 和 npm，可以使用：

```bash
npm install -g @openai/codex
codex --version
```

### macOS：Homebrew

```bash
brew install --cask codex
```

### Windows 建议

Windows 新手可以优先使用 ChatGPT 桌面端。如果希望使用 CLI，可先安装当前 LTS 版 Node.js，再在 PowerShell 或 Windows Terminal 中使用 npm 安装。

如果项目本身主要运行在 Linux 环境，也可以使用 WSL2，在 Ubuntu 终端中按照 macOS/Linux 的方式安装。不要在同一个任务里混用 Windows 路径和 WSL 路径，以免依赖与权限状态不一致。

## 四、第一次启动与登录

先创建一个测试项目：

```bash
mkdir codex-demo
cd codex-demo
git init
codex
```

第一次运行时，Codex 会提供登录方式：

### 方式一：使用 ChatGPT 账号登录（推荐个人用户）

选择 **Sign in with ChatGPT**，在浏览器中完成登录。之后的 Codex 使用量计入当前 ChatGPT 套餐。

### 方式二：使用 API Key

API Key 更适合自动化、CI 或希望完全按 API 用量付费的用户。使用 API Key 时，费用由 OpenAI API 平台单独计算，不能使用 ChatGPT 会员额度，而且部分云端功能不可用。

> ChatGPT Plus/Pro 和 OpenAI API 是两套独立的计费系统。开通 ChatGPT 会员不会自动获得 API 余额，充值 API 余额也不会自动升级 ChatGPT 会员。

## 五、完成第一个 Codex 任务

进入 Codex 后，建议按“了解 → 计划 → 修改 → 验证”的顺序工作。

### 1. 先了解项目

```text
请阅读当前项目，告诉我目录结构、运行方式和可能的入口文件。暂时不要修改。
```

### 2. 让它先给计划

```text
我要增加一个深色模式。请先调查现有样式体系，给出最小修改计划和验证方法，不要立即编辑。
```

### 3. 执行一个范围明确的修改

```text
按照刚才的计划实施，只修改与深色模式有关的文件。保留现有功能，完成后运行构建和相关测试。
```

### 4. 审核结果

```text
请总结修改了什么、验证了什么、还有哪些风险，并展示关键差异。
```

最后自己再运行：

```bash
git status
git diff
```

确认修改范围正确后再提交代码。

## 六、CLI 常用命令

| 命令 | 作用 |
|---|---|
| `/init` | 在项目中创建 `AGENTS.md`，记录构建命令、代码规范和协作要求 |
| `/status` | 查看当前会话、模型、权限和剩余使用情况 |
| `/permissions` | 调整 Codex 可以读取、修改或执行命令的权限范围 |
| `/model` | 选择模型和推理强度 |
| `/review` | 审查未提交改动、提交或相对某个分支的变化 |
| `codex resume` | 恢复之前保存的会话 |
| `codex exec "任务"` | 非交互执行任务，适合脚本和 CI |

可以在项目根目录运行 `/init`，然后把项目的固定规则写入 `AGENTS.md`：

```markdown
# 项目协作说明

- 修改前先阅读 README.md
- 使用 npm run dev 启动开发环境
- 提交前运行 npm test 和 npm run build
- 不要修改 dist、public/build 等生成目录
- 不要把密钥、令牌或本地配置提交到 Git
```

这样后续每个 Codex 任务都会更容易遵循同一套规则。

## 七、怎样描述任务效果更好？

一个好任务通常包含五部分：

1. **目标**：最终要实现什么。
2. **范围**：可以或不可以修改哪些区域。
3. **现状**：目前行为、报错或相关背景。
4. **约束**：兼容性、性能、样式和安全要求。
5. **验收**：需要运行哪些测试，怎样算完成。

例如：

```text
修复移动端导航按钮错位问题。

范围：只修改导航模板和自定义 CSS，不重构主题。
约束：保留桌面端布局，兼容 390px 宽度，深浅模式都要正常。
验收：运行构建，并在首页和文章页检查搜索、主题切换和菜单按钮是否对齐。
```

这比一句“帮我修一下导航”更容易得到稳定、可验证的结果。

## 八、如何通过官方渠道开通会员

Codex 已包含在 ChatGPT 的 Free、Go、Plus、Pro、Business、Edu 和 Enterprise 套餐中，但不同套餐的模型、额度和功能不同。

截至本文整理时，个人用户常见选择为：

| 套餐 | 官方标价 | 更适合 |
|---|---:|---|
| Free | 0 美元/月 | 偶尔体验短任务 |
| Go | 8 美元/月 | 轻量编程任务 |
| Plus | 20 美元/月 | 每周进行若干次较完整的编码任务 |
| Pro | 100 美元/月起 | 高频使用，希望获得更高 Codex 限额 |

具体价格、税费、地区可用性和权益可能变化，以 [官方套餐页面](https://learn.chatgpt.com/docs/pricing) 与付款页显示为准。

### 官方订阅步骤

1. 打开 [ChatGPT 官方网站](https://chatgpt.com/) 并登录自己的账号。
2. 点击左下角头像或账户菜单，找到 **升级套餐 / Upgrade plan**。
3. 根据需要选择 Plus 或 Pro。
4. 进入 OpenAI 官方结算页面，核对账号、套餐、周期、币种和税费。
5. 使用结算页面实际提供的支付方式完成付款。
6. 返回 ChatGPT，在账户设置中确认套餐已经生效，再使用同一账号登录 Codex。

支付方式会受到国家或地区、发卡机构、币种和账户状态影响。页面没有提供的支付方式，不代表可以通过第三方绕过。付款失败时，优先检查账单地址、银行卡是否支持国际或线上交易，以及账号所在地区是否属于官方支持范围。

### 不建议使用“代充”或共享账号

- 付款账号和使用账号可能不一致，续费、退款或申诉困难。
- 共享账号会暴露聊天记录、代码和项目文件。
- 来源不明的低价会员可能涉及盗刷、撤单或违反服务条款。
- 对方如果掌握账号、邮箱或验证码，可能随时取回账号。

最稳妥的方式始终是：**在自己的 ChatGPT 账号中，通过 OpenAI 官方结算页面订阅。**

## 九、Plus、Pro 和额外额度怎么选？

### 普通个人用户：先选 Plus

Plus 已包含 Codex 网页端、CLI、IDE 扩展等主要入口，适合学习、个人项目和每周若干次集中开发。第一次付费没有必要直接购买最高套餐，可以先观察一到两周的实际使用量。

### 高频开发者：再考虑 Pro

Pro 提供比 Plus 更高的 Codex 使用限额。复杂项目、长时间会话、大量工具调用和云端任务都会更快消耗额度，因此是否升级应根据使用面板决定，而不是只看消息数量。

### 达到套餐限额后

官方文档说明，Plus 和 Pro 用户达到包含额度后，可以在功能开放的账户中购买额外 ChatGPT credits 继续使用，不必立刻升级套餐。也可以改用更轻量的模型、缩小任务范围，或等待额度恢复。

### 查看使用情况

- 在 Codex CLI 中输入 `/status` 查看当前会话与剩余额度信息。
- 在 ChatGPT 的使用面板查看套餐和消耗情况。
- 如果额度消耗过快，减少无关文件、缩短上下文，并把大型需求拆成几个可验证的小任务。

## 十、ChatGPT 会员与 API 充值的区别

| 项目 | ChatGPT Plus / Pro | OpenAI API |
|---|---|---|
| 主要用途 | ChatGPT、Codex 产品和个人交互 | 程序调用、自动化、服务端与 CI |
| 登录方式 | ChatGPT 账号 | API Key |
| 计费方式 | 月度套餐 + 可选 credits | 按模型 Token 和工具调用量计费 |
| 是否互通 | 不包含 API 余额 | 不会升级 ChatGPT 会员 |
| Codex 云端功能 | 按套餐提供 | API Key 模式下部分功能不可用 |

如果你的目标只是日常使用 Codex，不需要开发自己的 AI 接口，通常订阅 ChatGPT Plus 更直观。

如果需要在脚本、服务器或 CI 中调用模型，则应在 [OpenAI API 平台](https://platform.openai.com/) 单独配置付款方式和用量上限。务必设置预算提醒，API Key 只能保存在环境变量或密钥管理服务中，不能写进公开代码仓库。

## 十一、安全使用建议

- 第一次处理陌生项目时，先让 Codex 只读分析，不要立即开放全部命令权限。
- 开始修改前创建 Git 提交或新分支，保持随时可以恢复。
- 仔细阅读即将执行的安装、删除、数据库和部署命令。
- 不要把密码、API Key、Cookie、私钥或生产数据库导出内容粘贴进对话。
- 修改后必须运行测试、构建或静态检查，不能只看 Codex 的文字总结。
- 涉及付款、部署、发布、删除数据等不可逆操作时，保留人工确认步骤。

## 十二、常见问题

| 问题 | 建议处理方式 |
|---|---|
| `codex: command not found` | 重开终端，检查全局 npm 路径或重新运行官方安装脚本 |
| 登录后仍提示无权限 | 确认 Codex 与 ChatGPT 使用同一个账号，并检查套餐和工作区 |
| npm 安装权限错误 | 使用 Node 版本管理工具，避免直接用管理员权限长期安装全局包 |
| Codex 修改范围太大 | 在任务中明确允许修改的目录和禁止修改的文件，并要求先给计划 |
| 使用额度下降很快 | 减少无关上下文，使用更轻量模型，把长任务拆成多个小步骤 |
| 会员已经开通但 API 无余额 | 两套计费系统独立，需要在 API 平台单独设置付款方式 |
| 付款失败 | 以官方结算页信息为准，检查地区、账单地址和发卡机构限制，不使用非官方代充 |

## 总结

Codex 的入门流程可以归纳为五步：

> **选择桌面端或 CLI → 登录 ChatGPT 账号 → 用测试项目熟悉权限 → 从小任务开始 → 审核并验证修改**

对于大多数个人用户，推荐组合是：

> **ChatGPT Plus + Codex 桌面端或 CLI + Git 检查点 + 明确的任务与验收标准**

会员只决定访问入口和使用额度，真正影响结果的仍然是任务范围、上下文质量和验证流程。先让 Codex完成一个小而完整的修改，再逐步扩展到真实项目，会比一开始交给它一个模糊的大需求更稳妥。
