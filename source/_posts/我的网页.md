# 我用纯前端做了两个「给自己用」的小工具

> 没有数据库，没有登录注册，打开浏览器就能用。这可能是前端最朴素的样子。

---

## 起因

生活中总有些小需求，大材小用装个 App 嫌重，用 Excel 又不够直观。比如和朋友出去旅行回来算账，或者想记录一下每天的学习时间线。

市面上的工具当然有，但总觉得「差那么一点」——不是多了广告，就是逼我注册账号，要么功能臃肿到找不到入口。

于是我想：我自己会写前端，为什么不给自己搓一个？

于是就有了这两个小东西。

---

## 项目一：多人旅行 AA 结算器

### 解决什么问题？

三五好友出去玩，你请了晚饭，他垫了门票，我付了打车费……回来之后最头疼的就是算账：谁该给谁多少钱？

手动算容易出错，用群收款又不够灵活（比如有的人只参与了其中一顿饭）。

### 核心逻辑

每个人有一个「已垫付金额」和一个「应承担金额」，两者相减得到净额：

- **净额 > 0**：别人欠你钱
- **净额 < 0**：你欠别人钱

然后用一个贪心算法做转账匹配——每次找欠最多的人和该收最多的人配对，取最小值转账，循环直到全部归零。这样能把转账次数压到最少。

### 功能清单

- 参与人管理、消费录入（金额、垫付人、分摊人、标签、备注）
- AA 核心结算 + 清晰的转账建议
- 按标签统计消费，配一个饼图
- 本地 LocalStorage 保存，支持 JSON 导入/导出
- 结算报告一键导出 PNG
- 手机端做了卡片化适配，按钮也够大

## 项目二：学习日志时间轴

### 解决什么问题？

备考或自学的时候，我想知道：今天到底学了几个小时？哪些时段是「计划了但没做」的？哪些时段是「额外多学」的？

传统待办清单只有「做没做」，没有「什么时候做的、做了多久」这层信息。

### 交互设计

页面是双栏结构，左边是**计划区**，右边是**记录区**，中间一条小时轴。

添加事件的方式很直觉：

1. 点「在时间轴选时间」
2. 鼠标移动，会看到一个吸附光标和当前时间提示
3. 点击确定起点（出现橙色标记）
4. 再点击确定终点
5. 弹窗里填学科和内容，保存

事件以紧凑的箭头形式显示，双击编辑，右键删除。导出的 PNG 是纯白背景，干干净净，方便贴到笔记里。

### 其他功能

- **专注计时**：正计时/倒计时，结束后自动写入记录区
- **复习任务**：根据学习记录生成复习计划，按今天/本周/本月筛选
- **撤销/重做**：`Ctrl+Z` / `Ctrl+Y`
- **可调设置**：起始小时、小时高度、双栏占比、学科颜色……

## 共同的设计哲学

这两个项目有几个共同点，也是我给自己定的约束：

| 原则 | 说明 |
|------|------|
| **零后端** | 没有服务器、没有数据库、没有 API |
| **零登录** | 打开就用，不收集任何信息 |
| **数据在本地** | `localStorage` 保存，JSON 导入/导出做备份 |
| **零构建** | 不需要 `npm install`，不需要 webpack，浏览器直接打开 |
| **单文件可用** | 每个项目就是 `index.html` + `styles.css` + `app.js` |

技术上没有什么高深的东西。AA 结算是一个贪心算法，时间轴是一些 DOM 计算和事件监听，饼图用 Canvas 画。但「够用」本身就是最好的架构。

## 一点感想

写这两个工具的过程中，我最大的体会是：

**给自己用的东西，不需要考虑「通用性」。**

不用做用户系统，不用做多租户隔离，不用写单元测试覆盖率，不用考虑并发。我只需要问自己一个问题：「这个功能我自己用不用得上？」

用得上就加，用不上就砍。这种「自私的开发模式」反而让产品异常精简。

当然，纯前端也有代价——换台电脑数据就没了。所以我在两个项目里都加了 JSON 导出。这是最低成本的「云备份」。

---

## 最后

如果你也有类似的小需求，不妨自己动手写一个。不需要框架，不需要部署，一个 HTML 文件就能开始。

前端最初的样子，不就是这样的吗？
